## ⚠️ It deploys on push to `main`

The Vercel project is git-connected with `main` as the production branch, so a
push publishes to thegospelandai.com. There is no staging. A docs-only commit
still triggers a production build.

Before pushing: confirm the branch, run `git log @{u}..HEAD`, and account for
every commit.

## Commands

- `npm run dev` — `vercel dev`. **Pin it to port 3012** (`vercel dev --listen 3012`);

  first if anything seems to be holding it.

- `npm run ingest` — `scripts/ingest.js`: fetch a transcript, chunk it, embed
  it, store it. This spends OpenAI credit and writes to production Supabase.

## Architecture

Static HTML with Vercel serverless functions under `api/`. No framework, no
build step — the pages are served as written, which is why they load fast and
why there is no bundler to configure.

```
Resources (YouTube, articles)
   │  scripts/ingest.js — fetch transcript, chunk, embed
   ▼
Supabase pgvector  ──►  api/chat  ──►  OpenAI chat  ──►  answer + sources
```

- `index.html` — landing page with the live AI companion.
- `resources.html` — browsable, searchable catalog.
- `widget.js` + `embed.html` — one-line embed for third-party sites, isolated
  in a shadow DOM so a host page's CSS cannot reach it.
- `api/` — the serverless functions, including `/api/chat`.
- `lib/` — shared helpers. `db/` — schema. `test/` — the Node tests.

Retrieval is semantic: a question is embedded and matched against transcript
and article chunks by meaning, and the answer is generated from what came
back. **The model answers from retrieved sources, not from memory.** Keep it
that way — this is a Scripture-grounded product and an unsourced answer is
worse than no answer.

`/api/chat` is IP rate-limited through Upstash Redis and **fails open** when
Upstash is not configured, so a missing credential degrades to no limiting
rather than to an outage. That is deliberate; know it before relying on the
limit.

## Security

- `.env` is gitignored and holds five keys, including
  `SUPABASE_SERVICE_ROLE_KEY` and `OPENAI_API_KEY`. It is `chmod 600`.
  **Never let a service-role key reach the browser.** Anything privileged
  belongs in `api/`, which runs server-side.
- `ADMIN_PASSWORD` guards `admin.html`. It is a single shared password, not an
  identity system; treat the admin page as protected by obscurity plus that
  one secret, and do not put anything there that would be damaging to leak.
- `.env` and `.vercel/project.json` do not come with a clone. If this repo is
  cloned somewhere new, they have to be brought across separately.
